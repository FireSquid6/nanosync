# Linux scan planner

`LinuxScanner.plan(priorManifest, revisionId, deviceId, master)` returns a validated manifest and a repeatable `chunks(knownObjectIds?)` async generator. Pass the manifest, sorted authenticated prior references (including evicted files), and `plan.chunks(new Set(knownReferences.map(r => r.objectId)))` to the Step 9 publisher. Only supply prior references actually required by the new manifest. If a remote-known reference needs repair, omit it from the set and supply its verified frame instead. Frames are encrypted in natural manifest file/chunk order on demand; no 50 GB buffer or spool is held. Do **not** commit the plan until publication/application succeeds. A failed publication needs a new plan/revision, and an unresolved frozen proposal must be resolved before retrying.

`LinuxWatcher.start()` watches known directories; call `ready()` periodically, and on `true` run `plan()` and `start()` again to refresh watches. Events, overflow, startup, and restart all cause a **full** scan; event names are never trusted for deletions. `notify()` supports external watchers. Defaults: 250 ms quiet debounce, then two identical metadata snapshots at least 500 ms apart; 256-event batch overflow; two scan workers (maximum eight). `ready()` is intentionally pollable with an injected clock. This keeps incomplete editor saves out of a batch; streaming additionally verifies dev/inode, size, mtime, ctime and mode before/after each file. Stable snapshot is a heuristic, not a filesystem transaction: changes during a multi-file publish must be handled by another scan.

The ordinary-data root must be owned by the current user, not a symlink, and contain only owner-owned regular files and directories. Symlinks, hardlinks, special files, ambiguous case names, unsafe/NFD names, and files larger than 50,000,000,000 bytes fail the batch. Scan errors are not interpreted as deletion. Keep the private `ClientLocal` directory **outside** the data root. `recordScan` stores filesystem IDs for subsequent rename detection; the caller must commit only after successful reconciliation. The result reports consumed suppression matches so the daemon can avoid echoing an applied remote change.

Delete/recreate assigns a new live ID. If an old tombstone occupies the name, it keeps its ID but is renamed deterministically to a bounded ` (deleted <full UUID>)` archival name; deleted parent directories' tombstones are moved to the nearest surviving directory (or root). Exhausted archival names fail visibly. Evicted live entries retain their namespace; a new local object at the same path is an explicit collision requiring reconciliation, never an inferred resurrection or deletion.
