# Linux daemon

`startDaemon({ clientDirectory, syncDirectory, vaultId, deviceId, masterKey, baseUrl, token })` starts the continuous Bun daemon. `stopDaemon(daemon)` shuts it down. The CLI uses `daemonCommand` for status, sync, pause, resume, history, restore, conflicts, evict, download and doctor. Status reports `state` and `exitCode` separately from activity `phase`, observed/accepted/applied heads, remote-only/downloaded file counts, pending recovery work and the last error. `headsConverged` means only that durable heads agree at the last observation; it does not claim that subsequent local edits have been scanned. `synchronized` additionally requires an unchanged read-only filesystem metadata inventory, no pending work, no open conflict, and no evicted remote-only files. The caller must provision the approved device credential and unlocked vault master key; the daemon never obtains these through IPC.

The client directory must be owner-only (`0700`); the IPC secret, socket and startup gate are owner-only (`0600`). A second owner fails closed. The gate publishes a complete PID and Linux process-start-time record atomically. Startup removes it only when that process identity is definitively gone, and recovers an orphaned socket only after a failed connection under the gate. Malformed, unsafe or unverifiable gate state fails closed rather than guessing. Never share the client directory with another user. This is a local privileged IPC interface, not a network service.

Every pass replays durable apply intents and the exact frozen head request before scanning. Filesystem notifications are hints; a periodic full scan catches missed events. An unsafe tree, changed file during publication, missing authentication, non-direct merge ancestry, or repeated contention is left visible as an error rather than being marked synchronized. Server transport needs an externally trusted TLS/VPN boundary.

Hydration is local-only: it verifies the authenticated accepted manifest and unchanged head, journals intent before removing a file, and downloads into a private stage before atomic no-replace link installation. Interrupted two-link installations are reconciled before watcher inventory on restart; an unrelated target is never replaced. Restore proposals are classified atomically with their frozen wire request so an accepted restore is applied on restart, not mistaken for a merge.
