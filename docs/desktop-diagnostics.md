# Shared diagnostics and explicit export

`packages/client-service/src/diagnostics.ts` is the same report builder and writer for CLI and trusted desktop main-process callers. It imports no native toolkit, starts no process, probes no credential store and uploads nothing. Collection uses existing credential-decision, settings, removal and read-only sync-status metadata; it never opens a journal writer. Existing legacy credential-decision validation may validate protected-file credential records; diagnostics does not separately retrieve credentials.

```ts
collectDiagnostics(root, trustedRuntime, { includeIdentifiers: false });
exportDiagnostics(root, absoluteFilename, trustedRuntime, { includeIdentifiers: false });
// { version: 1, exported: true, includeIdentifiers: false }
```

The synchronous API accepts `DiagnosticsRuntime`: `applicationVersion`, `toolkitVersion` (actual Electrobun version or null), and `native` facts for `startup`, `tray`, `session`, `notifications`, `notificationActions`. Versions are numeric semantic versions, optionally with a bounded prerelease suffix. Each native fact is one of `available`, `unavailable`, `failed`, `not-probed`, `not-applicable`. Supply trusted build/adapter facts only, never renderer input, exception messages or an environment dump. CLI passes toolkit null and `not-probed` facts; it need not import desktop code or test GTK, a display, D-Bus or keyring. Native intent is not availability, and availability is not proof of delivery.

## Version 1 report

Reports are constructed field by field, not serialized status/credential DTOs:

- `version`, `complete`; build application, actual Bun, platform/architecture and supplied toolkit version.
- `schemas`: actual validated settings version (null when absent), per-binding validated observation versions or null. Journal and credential descriptor versions are null because existing safe status/decision APIs do not expose these versions. `supportedSchemas.journal: 7` describes implementation support, **not** a validated schema claim for any binding.
- Nonsecret credential decision: mode, decisionRequired, migrationPending, cleanupPending, phase, canRollback. Removal pending/phase, without its inventory or request ID.
- Binding count, aggregate conflicts and pending counts (`operations`, `transfers`, `applies`, `hydration`, `proposal`, `restore`, `reconciliation`). Unknown contributing facts make the aggregate null; an empty collection has zero aggregates. Connection/enrollment counts are not guessed from binding counts.
- Ordinal binding rows: phase, freshness, independent pause causes, owner kind/presence, numeric observed/accepted/applied head sequences, pending counts, conflict count, fixed safe error and issue codes. Unknown facts remain null, including never-started journals. No head UUIDs, owner instances, lock identities, PIDs, sockets or capabilities.
- The five supplied enum-only native facts.

`complete` concerns collection, not successful syncing. Per-binding status/observation failures, unavailable roots and removal suppression yield `complete:false` and explicit errors/issues, while known fields remain available. Null never becomes a fabricated zero or schema version. An unreadable root/settings/credential decision or unsafe binding inventory fails with `DIAGNOSTICS_COLLECTION_FAILED` **before** output creation. Valid pending migration and removal remain diagnosable without recovery. During migration the operational status reader refuses access, so diagnostics validates only protected nonsecret binding records (and validated removal bindings), leaves phase/owner-presence/heads/pending/conflicts/observation schemas null, emits `CREDENTIAL_MIGRATION_PENDING` issues, and marks the report `complete:false`. It reports the actual validated credential migration phase without reading separate credential records or invoking providers. Reports are point-in-time best-effort observations, not a transaction across a running owner.

Default reports contain no paths, filenames, URLs, aliases, device display names, UUID identifiers, environment, logs, database rows, file content, credentials, keys, tokens, recovery material, credential references/generations/hashes or inode identities. Only allowlisted protocol/local codes survive errors; raw remote error bodies and exception messages never enter the report or outward errors.

`includeIdentifiers:true` applies to this export only, is never persisted, and adds **only** `identifiers.bindings:[{ordinal,bindingId,root}]`. These are sensitive local paths/IDs: warn the user before sharing. URL/alias/device display name collection is deliberately omitted even with opt-in. Neither mode reads file inventories or exports secret references/hashes. Notification privacy settings have no effect on diagnostics redaction.

## Destination and durability

The user must explicitly choose an existing directory and new filename. Desktop authority belongs to trusted main: a native directory picker followed by a main-generated basename, **not** a renderer-provided path. This module supplies no picker, upload or integration side effect.

The writer accepts ordinary owned 0755 Documents directories as well as 0700 ones. It never creates destination directories, changes permissions, replaces an existing file or accepts an overwrite flag. Every ancestor must be a real nonsymlink directory, owned by the current user or root and not group/world writable; root-owned sticky ancestors such as `/tmp` are allowed. The destination parent itself must be current-user-owned and not group/world writable. Ancestry identity and realpath are checked before creation and around writes/flushes. The parent descriptor must match the inspected parent. Every export identity-bearing lstat/fstat uses `bigint:true`; device/inode, UID, mode and link-count checks retain exact BigInt values, including adjacent inode identities above 2^53.

Destination paths overlapping the client private root or any known bound root are rejected. This covers the client's settings, servers/credentials, journals, root markers, controls and diagnostic/notification state within those roots. For a missing bound root, the nearest existing ancestor and all its ancestry must be canonical real directories: a replaced symlink ancestor is refused even when the final root does not exist. Legitimate missing roots beneath safe real ancestors still allow explicit partial exports. Saved binding metadata and existing passive root checks are reused; no journal writer is acquired.

Collection occurs before acquiring a private synchronous diagnostics lease using the maintained `privateDirectory` and `acquireSyncLock` primitives on the same physical `registry-lock` used by mutations. Under that lease, export rereads the credential decision and authoritative binding registry, validates roots/overlap, and retains the lease through exclusive creation, writing, descriptor fsync and parent fsync. Cooperating connect/rebind/removal operations cannot publish a new sync root in that interval. This is deliberately not the mutation wrapper: valid pending migration/removal is allowed for these nonmutating metadata reads and external protected-file output only. No mutation guard is relaxed for any operational caller, and no recovery, secret retrieval, picker, IPC, native effect or settings mutation runs under this lease. Registry-before-settings lock ordering is preserved without nested settings locks. The lease may initialize the private `registry-lock` directory, but never destination directories. An actual live owner or unsafe lock still fails closed with a fixed diagnostics error: diagnostics does not steal or bypass a held lease. A later explicit connection after export is outside this lease's scope and can sync whatever files the user then chooses to connect. Unknown external server roots, mount aliases or unrelated client roots cannot be discovered by this root-scoped API: callers must not offer those locations as authorized export destinations.

Output uses `O_CREAT|O_EXCL|O_WRONLY|O_NOFOLLOW`, mode 0600. Existing regular files, symlinks (including dangling ones), hardlinks and directories all fail. Descriptor metadata must show an owned regular 0600 file with one link; pathname and descriptor identities are rechecked. Content is written/flushed through that descriptor, then its checked parent directory is fsynced. Any write, flush or identity failure returns no success. Failed newly created protected artifacts are retained for inspection rather than risking unlink of a substituted pathname; use a fresh filename when retrying. A retained file is not evidence of successful durable export.

Portable path-based POSIX checks are not a race-proof `openat`/directory-capability API. A malicious same-UID process or noncooperating administrator can rename ancestors between syscalls, briefly substitute/restore objects, or mutate files after final checks. Checks detect ordinary identity changes but cannot eliminate these races or make an export immutable. Use a trusted owned directory, avoid concurrent namespace mutation, and treat exported opt-in paths as sensitive. No private-state 0700 policy was weakened.

Errors are fixed `ClientError`s (exit 2), without underlying OS paths/messages:
`DIAGNOSTICS_INVALID_INPUT`, `DIAGNOSTICS_COLLECTION_FAILED`, `DIAGNOSTICS_DESTINATION_UNSAFE`, `DIAGNOSTICS_DESTINATION_EXISTS`, `DIAGNOSTICS_WRITE_FAILED`.

## Bounded checks

`packages/client-service/tests/diagnostics.test.ts` uses only disposable temporary roots and fake credential data. It covers allowlisting, null/validated schema and counter facts, secret/remote/env canaries in both modes, no store probe or separate secret reads, read-only collection, owned 0755 export/0600 output, exclusive collision handling, source-root/unsafe-parent rejection, descriptor/parent flush failures, target/parent substitution (including exact adjacent 64-bit inode identities), registry publication exclusion through parent fsync, authoritative registry rereads after collection, missing-root ancestor aliases, legitimate missing-root partial exports, real pending removal/migration journals with unchanged private inventories and memory providers, held-owner refusal without lock stealing, and fixed collection/input errors. Filesystem faults are synchronous injected barriers; no sleeps, user roots, GUI, real keyring, network or native notification service are used. CLI/GUI integration and real compositor/package acceptance are owned separately.
